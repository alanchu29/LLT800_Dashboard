# LLT800_Dashboard

部門 manager 的 review dashboard：一頁看完部門承接的案子、各 PFAM 的時程、人力資源與員工出差紀錄。
融合 [monica-npi-chart](../monica-npi-chart)（手填案子 / Phase 時程）與 [Gen12AMD_Pilot_gantt](../Gen12AMD_Pilot_gantt)（PFAM 排程 Excel、人力負載）的做法。

- **總覽**（首頁）：KPI（進行中專案、本週 task、逾期、今日忙碌人數、本月出差）；KPI 下方是「需要注意」（逾期 / 未指派 / 指派給已離開的人，每組先列 5 筆；全部沒有時自動隱藏）；「專案總覽」以日為單位列出**前 7 天到後 30 天**內未完成的 PFAM 與 task（含逾期）（依 Project 分組，可展開 / 收合），上方可展開「同時進行的 PFAM」柱狀圖（預設展開，與甘特同一條日期軸；每個工作天同時有 task 進行的 PFAM 數、依專案堆疊；同一 PFAM 多個 task 只算 1，Others 每個 task 各算 1；上限＝計入人力的在職人數（不含「不計入人力的人員」），超過標紅；點柱子可只看那天的 task）；人力熱度（不列「不計入人力的人員」；未來一個月，PFAM / Task 兩個分頁，預設 PFAM：每個工作日一格＝當天手上的 PFAM 數（Others 每個 task 算 1）或 task 數，頂列為部門忙碌人數）、近期出差（出差中與未來 60 天）。
- **專案甘特**：Project → PFAM → task 三層。甘特圖依 Phase 上色，有基準日的 task 顯示延遲 ▲ / 提前 ▼；可切換表格檢視、依廠區 / 負責人篩選、隱藏已完成。甘特圖可展開「PFAM 負載」柱狀圖（與總覽相同：期間內每個工作天同時進行的 PFAM 數，跟著廠區篩選；「全部專案」上限＝計入人力的在職人數，個別專案用「編輯 Project → PFAM 負載警戒上限」自訂，空白＝不設；預設展開；超過上限的日子整欄紅底、超出部分紅色；點柱子可標記該日，甘特只顯示那天進行中的 PFAM / task，可取消「只看這天」或清除標記，總覽同樣適用）。PFAM 列是帶專案色左邊條的標題列、Project / PFAM 的期間條只在收合時顯示（PFAM 為灰色括號狀；展開時由底下的 task 呈現），task 列縮排並以專案色引導線掛在 PFAM 下；同一 Project 內 PFAM 依第一個 task 的開始日排序（Others 最後），同一 PFAM 內 task 依開始日排序，未指定 Phase 的 task 也用灰色，不與 Phase 色混淆；PFAM 後的廠區 tag 依廠區上色（與出差地點同色）。名為「Others / 其他」的 Project 一律排在最後。每個 Project 內建一個「Others」PFAM（放不屬於其他 PFAM 的工作），排在最後、永遠顯示（即使 task 全完成或不在區間內），不能改名或刪除。新 Project 預設取還沒被其他 Project 用過的顏色。Project 有填「外部系統連結」時，標題旁會出現連結按鈕，文字為「連結名稱」（空白則為「開啟 … 系統」；Gen12 AMD 預設為「Gen12 AMD Pilot Dashboard」）。
  - 期間可選「前 2 週 + 後 3 月」（預設）/「未來 6 個月」/「今年」，或在「從 / 到」輸入任意區間；只顯示與期間重疊的 PFAM 與 task，時間軸自動填滿畫面寬度。
  - 從「需要注意」、首頁專案總覽或出差紀錄點 task 會跳到這裡定位：該 task 一定顯示（期間自動延伸、不受篩選影響）、所在 PFAM 展開、捲到畫面中並閃爍標示；「清除定位」回到原本期間。
  - 點 Project / PFAM 的箭頭或名稱即可展開 / 收合；「開啟 ›」進入該專案；編輯模式下滑過 PFAM 列會出現 ✎（編輯 PFAM）與 ＋（新增 task）。
  - 「**全部專案**」卡片：所有案子在同一條時間軸（Project 列 → PFAM 列，點 PFAM 展開 task），下方「人力分配」是每人時間軸（每人一列標題，底下每個 PFAM 一列，條上直接寫 task 名稱；人力資源頁相同）。
  - 單一專案：下方「人力分配」只列參與這個專案的人。
  - 人力分配的時間軸與上方甘特圖同一時間尺度，左右捲動會同步。
- **人力資源**：每個工作日「忙碌人數 / 在職人數」柱狀圖，滑過看誰忙誰空，點一下標記該日；「每人工作」列出每人目前任務（PFAM › task，剩幾天 / 逾期）與下一個 task（點 task 跳到專案甘特）；下方是每個人的 task 時間軸。
- **出差紀錄**：名冊（姓名、出差中、進行中 task 數、年度出差、下次出差）；出差紀錄（起訖日、地點、目的、關聯專案）、年度出差天數統計（依專案 / 依地點兩個分頁，預設依專案）與出差行事曆。
- **設定**：**員工名冊**（批次輸入姓名、改名、在職 / 離開、刪除）、Phase 清單與顏色、**假日**（逐筆新增或批次貼上，例如 `2026/2/14~2/22 春節`；不算工作日，甘特圖以灰底標示）、廠區 / 地點清單、不計入人力的人員（預設 Dixon，主管等不算進忙碌 / 在職人數與人力上限）、標紅規則、編輯密碼、匯入 / 匯出、Google Sheet 雲端同步。

> 開始使用正式資料時，先到「設定 → 員工名冊」輸入部門成員（一行一位或逗號分隔），之後 task 指派、人力資源與出差紀錄都會用到這份名冊。
>
> 第一次開啟看到的是**示範資料**：專案與 task 來自 MONICA 的匯出檔（Gen12 Excel 的 task 不在示範資料中，需要時自行匯入到 Gen12 AMD），員工姓名（標「示範」）、指派、進度與出差都是假的。到「設定 → 資料 → 清空專案與員工資料」即可開始建立正式資料。

## 快速開始（本機）

直接用瀏覽器開啟 `index.html`，不需要伺服器或安裝套件。

- 修改內容會自動存在這個瀏覽器的 localStorage。換電腦或清除瀏覽器資料前，請先用「設定 → 匯出 JSON 備份」保存。
- 右上角「✎ 編輯模式」開啟後才能新增或修改（可在設定加密碼，只用來防止誤改）。↶ / ↷（Ctrl+Z / Ctrl+Y）可復原或重做。
- 預設深色模式；右上角 ◐ 切換深色 / 淺色（會記住）。
- 右上角「？ 使用說明」（或按 `?` 鍵）開啟畫面中央的使用說明，預設跳到目前頁面的段落。說明內容在 `js/help.js`，新增或修改功能時記得一併更新。

## 資料結構

| 層級 | 欄位 |
|---|---|
| **Project** | 名稱、顏色、狀態（進行中 / 封存）、PFAM 負載警戒上限、外部系統連結與連結名稱、備註 |
| **PFAM** | 名稱、所屬 Project、廠區、備註 |
| **Task** | 名稱、PFAM、起日、迄日、指派人（多選）、已完成（勾選）、Phase；更多欄位：Section、LEAD 角色、基準起訖日、備註 |
| **員工** | 姓名、在職（取消勾選＝已離開，不計入人力，但保留歷史） |
| **出差** | 員工、地點、出發、返回、目的、關聯專案、備註 |

- Project / PFAM 的時程由底下 task 的最早起日與最晚迄日自動算出。
- task 只分「完成 / 未完成」（不計算進度 %）：勾選已完成 ＝ 已完成；過了迄日但未完成 ＝ 逾期；其餘依日期為進行中 / 未開始。Gen12 Excel 中進度 100% 的 task 匯入時視為已完成；舊資料的進度 % 會自動轉換（100% ＝ 已完成）。

## 人力資源的計算

- **在職人數**：在職員工扣掉「設定 → 不計入人力的人員」（預設 Dixon）。以下的忙碌 / 在職人數都只算這些人。
- **忙碌人數**：當天手上有任何進行中 task 的在職員工數。一個人同時有好幾件 task 也只算 1 人。
- **未指派**：當天有 task 沒有指派任何在職員工的 PFAM，**每個 PFAM 算需要 1 人**（同一個 PFAM 的多個未指派 task 不重複計算）。
- **標紅（超出部門人力）**，可在設定切換：
  - 預設「沒有人空著」：忙碌人數 + 未指派 PFAM ≥ 在職人數。
  - 或「忙碌人數 ≥ 在職人數的 N%」。
- 只算工作日（週一～五，扣除「設定 → 假日」裡的日子）。已完成的 task 從今天起不再佔用人力，過去的日子照實際區間計算。
- 可用專案晶片選擇要計入哪些專案（預設全部未封存的專案）。

## 年度出差天數

日曆年（1/1–12/31）、日曆天（含週末，起訖日都算），跨年的出差按天數拆到兩個年度。

## 匯入

都在「設定 → 資料」（需編輯模式），套用前會先顯示預覽，套用後可按「復原」。

### MONICA JSON

MONICA 的「Import / Export → 匯出 JSON」檔案。

- Series → Project、project → PFAM、Phase 原樣帶入 task（缺少的 Phase 會自動加入設定），task 名稱空白時以 Phase 名稱代替。
- PIC 依姓名比對員工名冊（不分大小寫，`/`、`\`、`,`、`、`、`&` 都視為分隔）；比對不到的會提示，也可勾選「自動新增為員工」。
- Phase：舊版 MONICA 的 `1st script rack / 2nd validation rack / 3rd FPY rack / Volume` 與新版的 `1st rack (DEV) / 2nd rack (VLD) / 3rd rack (FPY) / VB` 是同一組，會自動合併為新版名稱，舊代碼保留為別名，之後匯入新舊檔案都會歸到同一個 Phase。其他重複的 Phase 可在「設定 → Phase 清單 → 合併到」手動合併。
- 再次匯入新版：以 Series + project + Phase + task 名稱辨識同一個 task，**更新日期，保留網頁上的指派、完成狀態與備註**，舊日期成為基準（▲▼）。新檔裡沒有的 task 列出來，預設保留，勾選才刪除；只會比對檔案裡出現的 Series。

### Gen12 PFAM Excel

Gen12AMD_Pilot_gantt 使用的 NPI Dashboard Excel（例如 `To MSFT_Wiwynn NPI Dashboard_C419E_…xlsx`）。瀏覽器直接解析，不上傳到任何伺服器。

- 預設匯入到既有的「**Gen12 AMD**」Project（與 MONICA 的 Gen12 AMD 是同一個案子），不另建 Project；匯入畫面可改選其他 Project。
- 早期版本曾自動建立「Gen12 AMD Pilot」，與 Gen12 AMD 重複；每個瀏覽器第一次開啟新版時會自動移除它（只移除那個自動建立的 Project，可「復原」）。
- 排程日期用與 Excel 相同的 WORKDAY / 前置任務規則算出（沿用 Gen12 的排程引擎與匯入器）。Excel 隱藏的分頁與沒有日期（TBD）的 task 會略過。
- 同一 PFAM 的 **1st + 2nd build 合併**成一個 PFAM（規則與 Gen12 相同），Pre GA 等其他分頁各自一個。
- 預設勾選 **LEAD 含 STE 或 TE** 的 task（可在設定修改預設角色，或在預覽畫面改角色後按「依角色重新勾選」），再逐項勾選或以 PFAM 為單位全選。2nd build 中「沿用 1st」的區段不預先勾選，避免重複計算。
- 沒勾選的 task 會被記住，下次匯入仍預設不勾。
- 匯入後指派人是空的，到專案甘特逐一指派；重新匯入新版 Excel 時的處理方式與 MONICA 相同（以分頁 + WBS + task 名稱辨識）。

### 批次標記完成

「設定 → 資料 → 批次標記完成」：把結束日早於指定日期的未完成 task 一次設為已完成（整理舊資料用，可復原）。
2026-10 初版上線時，每個瀏覽器第一次開啟會自動把 **2026/9/1 以前**結束的 task 設為已完成一次（提示訊息可「復原」）。

### JSON 備份

「匯出 JSON 備份」的檔案可用「還原 JSON 備份」整份取代目前資料。這個選擇器也認得 MONICA 匯出檔與 Gen12 資料 JSON，會自動轉到對應的匯入流程。

## Google Sheet 雲端同步（選用）

讓全部門共用同一份資料。資料是**公開可讀**的（有網址的人就看得到，包括出差紀錄），寫入可用金鑰保護。

1. 建一張**全新空白**的 Google 試算表（每次同步會清空重寫各分頁，不要用有其他資料的試算表）。
2. `擴充功能 → Apps Script`，刪掉預設內容，貼上 [`apps-script/Code.gs`](apps-script/Code.gs) 整段，儲存。
3. （選用）`專案設定 → 指令碼屬性` 新增 `EDIT_KEY` = 任意密語。
4. `部署 → 新增部署作業 → 網頁應用程式`：執行身分「我」、存取權「**所有人**」，部署並完成授權，複製結尾是 `/exec` 的網址。
5. 打開 dashboard「設定 → Google Sheet 雲端同步」：貼上網址（有設 EDIT_KEY 就填寫入金鑰）→ 測試連線 → 勾「啟用雲端模式」→ 儲存設定。
6. 第一次請按「上傳本機資料到雲端」。之後修改會先存在本機，右上角出現「⇪ 同步到雲端」時按一下即可寫入。

- 試算表會有 `Projects / PFAMs / Tasks / Employees / Trips / Ignored / Meta` 分頁；`projectName`、`pfamName`、`assigneeNames`、`empName` 欄只是方便閱讀，讀取時不採用。
- 同步採整份覆寫 + 版本號檢查：如果別人先同步過，會詢問要覆寫雲端還是保留本機。
- `js/remote.js` 的 `DEFAULT_URL` 已填入部門的 Apps Script 網址：每個人開啟時**預設從雲端載入**；讀不到雲端（網路問題、Apps Script 冷啟動逾時或按「略過」）時才顯示這台電腦上次的資料，並可「重試」。
- 寫入由 Apps Script 的 `EDIT_KEY` 保護（網址是公開的，請務必設定）。

### 多人同時使用

同一份資料多個人在改，難免會踩到彼此。目前有三層保護：

- **開啟頁面不用等**：先顯示這台電腦上次的資料，雲端在背景更新（右上角顯示「雲端 · 更新中…」）。只有第一次造訪（本機還沒有資料）才會等。
- **只在有變動時才傳整份資料**：讀取時會帶上自己手上的版本號，雲端版本沒變就只回一個版本號，不重讀試算表 — 沒人編輯的日子，開頁面幾乎不花時間。
- **進入編輯模式前自動拉最新版**：分頁開一整天後才開始改東西，手上的基準版本已經是早上的了，存回去就會蓋掉別人的修改。所以按「✎ 編輯模式」時會先確認是不是雲端最新版，不是就先載入（會提示版本與最後修改的人）。讀不到雲端時會問要不要照樣編輯。
- **每一版都留快照**：每次寫入成功後，Apps Script 會把那一版資料存成 JSON 檔放到雲端硬碟的「LLT800_Dashboard 快照」資料夾（保留最近 30 版，檔名是 `llt800-v<版本>-<時間>-<人名>.json`）。萬一還是被蓋掉，從那裡下載檔案，用「設定 → 資料 → 還原 JSON 備份」就能還原 — 快照格式和「匯出 JSON 備份」相同。
  - 想放在特定資料夾：`專案設定 → 指令碼屬性` 新增 `SNAPSHOT_FOLDER_ID` = 資料夾 ID。
  - **快照功能需要雲端硬碟權限**：從舊版更新 `Code.gs` 後要重新部署並重新授權一次（`部署 → 管理部署作業` 更新版本，第一次執行會跳授權畫面）。快照失敗不會影響寫入，只會記在執行紀錄裡。

## 開發者

```bash
node tools/test_core.js            # 負載計算、出差天數、MONICA / Gen12 匯入與重新匯入；若找得到 Gen12 Excel，比對瀏覽器匯入器與 seed 完全一致
node tools/test_apps_script.js     # 以模擬的 Apps Script 環境測試 Code.gs：整份資料往返、版本衝突、寫入金鑰、日期格式
node tools/build_seed.js [monica.json]   # 重新產生 data/seed.js（示範資料，只含 MONICA）
```
